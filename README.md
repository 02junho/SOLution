## 무엇을 하나요

개인 카페 사장님이 매주 엑셀과 감으로 하던 두 가지 결정을 돕습니다.

| | 장보기 (매입) | 직원 근무표 (운영) |
| --- | --- | --- |
| 고민 | "원두·우유를 어디서 얼마나 살까?" | "이번 주 알바를 몇 명, 언제 쓸까?" |
| 입력 | 거래처 견적 문자 붙여넣기, 예산·배송 횟수는 말로 | 마이샵 매출이나 포스기 파일(엑셀·CSV), 직원 근무 가능 시간 |
| 계산 | 예산·배송 횟수·최소 주문·보관 한도·기간 끝 재고 한도를 지키면서 총액이 가장 적은 조합 | 하루 20번 시뮬레이션해 손님 대기를 목표(기본 5분) 안으로 맞추는 최소 인원, 주 15시간 미만 근무조 |
| 결과 | 두 안 비교, 거래처별 주문 문구, 예산이 모자라면 바꿀 값 제안 | 세 근무표(인건비 절약·균형·여유) 비교·추천, 새로 뽑을 직원, 줄 서는 모습, 인쇄 |

시연 예시(거래처 12곳): 가장 싸게 **₩113,280** · 한 곳에서 한 번에 ₩127,500 · 단가만 보고 고르면 ₩166,090(배송 4번·최소 주문 미달·보관 초과로 실제로는 주문 불가)

## 어떻게 동작하나요

```text
01 말하기        02 조건 확인          03 계산              04 결과·설명
사장님   ──▶   AI 에이전트    ──▶   계산 코드    ──▶   AI 에이전트
"장보기 계획     말한 조건 반영,       조건 지키는 조합,     결과를 쉬운 말로,
 세워 줘"        빠진 값은 되묻기      근무표 시뮬레이션     고르는 건 사장님
```

- **AI 에이전트가 하는 일**: 견적 정리, 품목 이름 맞추기, 빠진 값 되묻기, 쉬운 말 설명
- **AI에 맡기지 않는 일**: 숫자 계산은 코드(PuLP·SimPy)가, 최종 결정은 사장님이

화면은 시니어 사장님도 쓰기 쉽게 만들었습니다. 할 일을 말로 적거나 카드를 누르면 시작하고, 큰 글씨 모드와 사용법 안내가 있습니다.

## 구조

```text
사장님 브라우저 ──▶ frontend ──────▶ backend ──────────▶ ai-server ──────────▶ Claude API
  (쉬운 화면)       nginx · React     Spring Boot          FastAPI               말 해석 · 결과 설명
                                      업무 저장            계산 · 품목 검색
                                        │                     │
                                        ▼                     ▼
                                   PostgreSQL  ◀──────  품목 이름 맞추기 (RAG)
                                   업무·결과 기록        "맛있는우유" → 우유
                                   pgvector              KURE-v1 임베딩
```

| 영역 | 기술 |
| --- | --- |
| 화면 | React 19, TypeScript, Vite |
| 서버 | Spring Boot 4 (Java 21), Flyway |
| AI·계산 | FastAPI (Python 3.13), LangChain, Claude Sonnet 5.5, PuLP(구매 최적화), SimPy(근무표 시뮬레이션) |
| 검색 | KURE-v1 임베딩, pgvector |
| DB | PostgreSQL 16 (배포: AWS RDS, 프라이빗 서브넷) |
| 실행·배포 | Docker Compose, GitHub Actions, AWS EC2 · RDS |
