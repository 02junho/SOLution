# evals

기능별 평가 실행기. 정답은 구현 코드가 아닌 곳(손계산, 다른 팀원의 블라인드 정답, 독립 전수 열거)에서 가져온다.

## 구매 최적화 (`purchase/`)

```bash
cd ai-server
python -m evals.purchase.run                      # 결과 표 출력
python -m evals.purchase.run --out evals/results  # purchase_eval.md · purchase_eval.json 저장
```

| 파일 | 내용 |
| --- | --- |
| `purchase/cases.py` | 평가 사례와 기대 결과. 사례마다 정답 출처를 적는다 |
| `purchase/oracle.py` | 앱 코드·PuLP 없이 규칙만으로 다시 계산하는 정답(전수 열거)·기준선·검산 |
| `purchase/run.py` | 사례를 도구에 넣고 기대 결과·전수 열거와 비교, 돌려준 안을 다시 합산해 조건 확인 |
| `results/purchase_eval.md` | 마지막으로 저장한 결과 |

사례마다 세 가지를 본다.

1. 기대 결과: 응답 상태, 안 1·안 2·기준선 총액, 기준선이 어긴 조건, infeasible 원인
2. 독립 전수 열거: 가능한 묶음 수를 전부 세어 찾은 최저 총액과 같은지 (작은 사례만)
3. 검산: 돌려준 구매안을 다시 합산해 총액·필요량·보관 한도·기간 끝 재고 한도·최소 주문금액·배송 횟수·예산·입고 후 재고·주문 문구 금액이 맞는지

`tests/test_purchase_evals.py`가 모든 사례를 CI에서 돌린다. 계산 규칙을 바꾸면 사례의 기대 결과도 함께 고친다.

절감률은 합성 사례에서 최적화와 기준선(단위단가순 담기)을 비교한 값이다. 실제 매장 절감률이 아니다. 기준선이 조건을 어긴 사례는 절감률을 내지 않는다.

### 사례를 더할 때

- 정답은 손으로 계산하거나 다른 사람이 계산한 값을 쓴다. 도구를 돌려 나온 값을 정답으로 옮겨 적지 않는다.
- `source`에 누가 언제 계산했는지 적는다.
- 작은 사례는 `"oracle": True`로 전수 열거와도 비교한다.
